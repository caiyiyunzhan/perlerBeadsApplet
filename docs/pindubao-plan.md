## 一、拼豆品类研究

### 1.1 拼豆是什么

拼豆（英文 Perler beads / fuse beads，又称熨烫豆、拼拼豆豆）是一种像素艺术手工：

- **材料**：空心塑料小圆管豆，常见材质为低密度聚乙烯（LDPE），直径分 **5mm 标准豆** 与 **2.6mm 迷你豆** 两档。
- **玩法**：按照图纸把豆子一颗颗插在带凸钉的拼板上，铺一层熨烫纸，用电熨斗中温熨烫，豆子受热熔合、冷却定型，成为一体的像素作品。
- **文化背景**：起源是欧美儿童手工教具，近年在国内因为像素艺术、动漫二创、表情包文化在成人手工圈爆火，常见作品包括动漫立牌、情侣头像挂件、冰箱贴、杯垫等。
- **IP 引流**：游戏像素角色是重要流量场景，"星露谷物语"角色拼豆曾带动一波入坑潮（已有玩家因此自研辅助工具）。
- **规格互不兼容**：5mm 与 2.6mm 拼板孔径不同不可混用；同一作品也不建议混用品牌（热缩率、色号、批次色差差异）。

### 1.2 玩法分类

**按形态**

| 玩法 | 说明 | 人群 |
|------|------|------|
| 平面拼豆 | 主流玩法，方形拼板单层拼摆熨烫 | 全人群 |
| 立体拼豆 | 多片平面件组合成盒子、人偶、摆件等立体结构 | 进阶玩家 |
| 异形拼豆 | 圆形、心形、星形、六边形等异形拼板 | 全人群 |

**按规格**

| 规格 | 特点 | 适合人群 |
|------|------|---------|
| 5mm 标准豆 | 颗粒大、易操作、容错率高，画面偏卡通色块 | 儿童、新手、教学 |
| 2.6mm 迷你豆 | 像素密度约 3.7 倍，画面细腻，可做写实肖像 | 16 岁+ 进阶、展示级作品 |

**按熨烫方式**

行业已形成标准术语，图纸导出应支持风格说明：

| 熔法 | 英文 | 效果 | 难度 |
|------|------|------|------|
| 部分熔 | Partial Melt | 保留豆孔立体感，"像素感"强 | 新手友好 |
| 完全平融 | Flat Melt / Pixel Melt | 豆孔闭合、表面平滑 | 难度高 |
| 背熔 | Back Melt | 背面平融固定、正面保留立体 | 兼顾坚固与质感 |

**熨烫工艺要点**（教程内容与图纸设计的依据）

* LDPE 熔点约 105-115°C：温度过低仅软化易断裂，过高完全熔化塌陷。
* 颜色吸热速度不同：黑色/深色快，白色/透明慢，同一作品熔化不均是常态。
* 家用熨斗：关蒸汽、中档、持续画圈，同一位置停留不超过 3 秒；进阶用 Cricut EasyPress / 小型压烫机。
* 介质层：助烫纸（哑光、日常练习）、熨烫膜（高光透明可观察进度）；蜡纸禁用（融化污染）。
* 胶带法（Tape Method）：贴胶带把豆子从钉板转移后翻面熨烫，避免钉板受热变形；需打孔排气防爆孔。
* 新手黄金法则：低温慢熨、大作品分区熨烫且边缘优先、冷却压重物 10-20 分钟。
* 常见失败：爆孔、胶带残留、翘曲、熔化不均、断裂、哑亮混合面。
* 图纸打印用法：300 DPI 打印后垫在透明拼板下方照着铺豆；大图分块打印；先铺大面积色块再铺细节。

**后链路：裱框与展示**

LDPE 长期暴露会变脆褪色，展示级作品会裱框（立体中空框避免挤压，如宜家 HOVSTA 深框）、深色背景纸衬托、无痕胶点固定、泡沫胶做悬浮效果；挂件类留孔穿绳做钥匙扣、包挂。

**按成品应用**

钥匙扣挂件、冰箱贴、杯垫、立牌摆件、耳环饰品、画框装饰、车载挂饰等。

**特殊豆材**：透明豆、夜光豆、珠光豆、荧光豆，用于特效点缀。

### 1.3 色号体系（色卡）

色号是拼豆的"硬通货"：玩家按色号购买散豆补货，图纸必须标注**色号 + 用量统计**，否则无法备料。不同品牌色号不通用，颜色有细微差异，官方建议同一作品用同一品牌。

**真实色数规模**（beadcolors 开源色卡数据库实测）

| 体系 | 说明 | 色数规模 |
|------|------|---------|
| MARD | 国产性价比主流；完整版 291 色，常用基础版 221 色 | 221 / 291 色 |
| COCO | 国产品牌 | 约 150 色 |
| 漫漫 | 国产品牌，色号字母+数字 | 约 150 色 |
| 盼盼 | 国产品牌，纯数字色号 | 250+ 色 |
| 咪小窝 | 国产品牌，纯数字色号 | 280+ 色 |
| Perler | 国际品牌（美国），标准 / Mini / Caps 三条线 | 103 / 41 / 26 色 |
| Hama | 欧洲品牌，Midi / Mini / Maxi 三规格 | 92 / 78 / 25 色 |
| Artkal | 5 个系列：A / C / M（2.6mm）+ R / S（5mm） | 每系列 89-199 色 |
| Nabbi / Yant | 欧洲品牌 / 国产品牌 | 30 / 119 色 |

**MARD 色号系列结构**（291 色实测分布）：A(25) B(32) C(29) D(26) E(24) F(25) G(21) 为基础实色系；H、M、P、Q、R、T、Y、ZG 为透明 / 珠光 / 夜光等特殊效果系列。色号 = 系列字母 + 数字编号，选色器按系列分组更符合购买与收纳习惯。

**行业色卡数据规范**（beadcolors 数据库的启示）

1. 每个颜色除 HEX 外应带 LAB 值：感知色彩空间匹配（CIEDE2000 / OKLab）已是开源工具的共识方向，RGB 欧氏距离是初代做法。
2. 色卡带 symbol 符号字段：图纸小格子写不下色号时，用三角形 / 方块 / 圆点等符号代替色号，配合图例识别，这是印刷图纸的标配。
3. 色卡数据必须来源可追溯（记录贡献者与出处），版本化管理，支持社区纠错。
4. 同一品牌色卡有版本分层：MARD 基础版 221 / 完整版 291；色板组合分 72 / 96 / 144 / 168 色等档位，匹配新手到进阶套装。

**购买形态与收纳**：国内玩家典型购买方式是 MARD 收纳盒套装（几十格分格、按色号排布）+ 散豆按色号补货。已有玩家自研"色号 → 收纳盒格子位置"查询工具，证明找豆定位是真实高频痛点，也是差异化功能机会。

**关键结论**：本项目现有代码已有 MARD/COCO/漫漫/盼盼/咪小窝 **5 套色号、217 色**的 HEX 映射表（`src/utils/colorData.ts`），是极有价值的种子数据，新项目必须继承，并把色卡从"前端写死"升级为"数据库 + 接口动态下发"，以后新增品牌不发版。国际品牌数据建议以 beadcolors 开源数据库（CSV，含 LAB 值）为源，国产 5 品牌沿用现有映射并逐色校准。

### 1.4 用户画像与核心旅程

**用户群体**

1. 学生 / 年轻女性手工爱好者（主力）：做动漫角色、表情包、情侣挂件。
2. 亲子家庭：儿童启蒙手工，5mm 大颗粒为主。
3. 进阶玩家：写实肖像、2.6mm 迷你豆大作品。
4. 半商业用户：手工店代做、市集摊主，需要高效出图纸和备料清单。

**核心旅程（图片转图纸场景）**

找图 / 拍照 → 裁剪构图 → 选风格滤镜 → 选尺寸（对应板子大小）→ 选色卡（品牌）→ 控制颜色数 → 预览成品效果 → 生成图纸（色号+用量）→ 按图纸摆豆熨烫 → 完成打卡。

**痛点（产品机会）**

1. 图片转图纸目前依赖电脑工具，手机端体验缺失。
2. 色号对照混乱，各品牌互不通用，新手不知道选哪套。
3. 备料难：不知道买哪些色号、各买多少。
4. 好图纸分散在社交平台，没有聚合的模板库。
5. 摆豆过程漫长，缺乏进度管理和打卡激励。
6. 从收纳盒找对应色号豆子费时费力。
7. 屏幕颜色与实物有色差（显示器、光照、批次），大量采购前无法预判。
8. 大作品跨多块拼板，缺少底板布局与接缝指导。

### 1.5 玩家真实工作流（按色制作）

拼豆的实际制作不是"逐格拼"，而是**按颜色批量铺豆**：先把色号 A 的豆全部摆完，再摆色号 B，依此类推。这也是材料清单必须按色号统计的原因。高效工具应提供"按色聚焦"模式：高亮当前色号、逐色标记完成、自动切换下一色。该工作流已在豆格工坊（按色制作助手）和 perler-beads-ai（专心拼豆模式）中被验证为真实需求。

### 1.6 竞品参考

| 产品 | 形态 | 核心功能 | 关键短板 |
|------|------|---------|---------|
| Zippland perler-beads（933 星） | 网页 | 主导色像素化、BFS 杂色合并、背景移除、颜色排除重映射、采购清单 | 无小程序（Roadmap 未做）；AGPL 协议不可闭源商用 |
| perler-beads-ai（293 星，当前小程序母项目） | 网页 + CF | AI 生图优化（即梦 API）、17 项编辑功能、专心拼豆模式 | 无社区、无小程序；Apache-2.0 可合法继承 |
| Pindo（279 星） | 网页 / PWA / 安卓 | 8 品牌色板、图纸拍照识别、色板系列过滤、按豆数定尺寸 | GPL 协议、无社区 |
| 豆格工坊（155 星） | 网页 / PWA / 离线 HTML | 实体底板布局、按色制作助手、接板线、CSV/JSON 工程、色差警示 | 无社区、无 AI；Apache-2.0 可商用复用 |
| Pindou 社区版 | 网页 + 桌面 | WebGL 编辑器、OKLab 感知匹配、GitHub 登录画廊、Photo/Illustration 双模式 | 微信生态之外 |
| Jett-Wu 编辑器（41 星） | 网页 | 多图层、参考图临摹、Three.js 3D 预览、按包数估算、孤豆检测、Excel 导出 | 桌面优先 |
| PixelBeads | 网页 | 教程内容最全、三入口工具、作品集 | 无小程序、无社区激励 |

**结论**：主流工具全部是网页/桌面形态，**微信小程序生态内没有功能完整的拼豆工具**（Zippland 的 Roadmap 也确认了这一空白），这正是"拼豆堡"的机会窗口。功能层面行业已收敛出标准答案：主导色量化、杂色合并、背景移除、按色制作、用量清单。拼豆堡应以标准答案为基线，用"小程序便携性 + 社区模板广场 + AI 优化 + 豆库闭环"做差异化。

## 二、产品定位

> **拼豆堡 = 手机上最好用的拼豆图纸工具 + 活跃的拼豆模板社区。**

一句话：让任何人 3 分钟把一张图变成"色号 + 用量 + 可直接照着拼"的专业图纸；让玩家在模板广场找图、晒图、打卡，形成内容飞轮。

**差异化抓手**

1. 色卡系统产品化：多品牌色卡动态切换、色号搜索、"我的豆库"缺料提醒。
2. 图纸质量：专业减色算法 + 色卡最近色匹配 + 成品效果预览（圆孔质感渲染）。
3. 社区飞轮：官方模板保底 + 用户投稿激励 + 完成打卡晒图。
4. 备料闭环：图纸一键生成"缺料购物清单"（色号 x 数量），远期对接材料包电商。

## 三、小程序端功能规划

### 3.1 首页 / 模板广场（Tab 1）

* 瀑布流模板卡片：预览图、标题、网格尺寸、色数、点赞/收藏/使用数。
* 分类频道：推荐、动漫角色、表情包、文字数字、动物、食物、节日、风景、肖像、立体组合。
* 搜索：标题/标签/色号。
* 官方模板 + 已审核用户投稿混合展示，可按来源筛选。
* 模板详情：大图预览、色号用量列表、"一键使用"（跳编辑器加载）、收藏、举报。

### 3.2 图纸工坊（核心工具，Tab 2）

五个入口：

1. **图片转图纸**（核心中的核心）
   * 相册/拍照导入。
   * 裁剪：自由比例 + 预设比例（1:1、4:3、16:9），旋转、镜像。
   * 风格处理：原图、卡通增强（减色+描边）、复古、高对比、柔和、黑白；人像模式（肤色卡优先、细节保留）。
   * AI 优化（差异化功能）：上传后可选 AI 预处理，把照片转成干净的像素风 / Chibi 插画再量化（参考 perler-beads-ai 已验证的提示词方案，如火山引擎即梦 API）。
   * 尺寸选择：宽 8-300 格，按 5mm/2.6mm 显示成品实际尺寸（如 58 格 x 5mm = 29cm）；按规格智能推荐格数（5mm 建议 100-200 格、2.6mm 建议 200-300 格，来源为社区教程共识）。
   * 色卡选择：MARD / COCO / 漫漫 / 盼盼 / 咪小窝 + Artkal、Perler、Hama（国际品牌数据源 beadcolors 开放数据库）；色板档位可选（如 MARD 基础 221 / 完整 291、新手 96/168 色板）。
   * 颜色数控制：8-100 色滑杆，实时预览。
   * 高级选项：抖动算法开关（Floyd-Steinberg）、Photo / Illustration 双模式（照片重过渡、插画保边缘）、跳过背景色、透明背景转白色。
   * 生成：预览成品效果（圆孔渲染，进阶可加 3D 质感预览）+ 图纸页（网格+色号+坐标+用量统计表）。
2. **图纸识别**（差异化功能）：给已有的无标注图纸或网图拍照，自动识别网格与颜色块，补齐色号标注与用量统计（Pindo 已验证该能力可行）。
3. **自由绘制**：网格画布（继承现有编辑器）+ 画笔/橡皮/吸管/填充/直线/矩形、参考底图描摹（透明度/位置/缩放可调）、多图层（隐藏/锁定/按图层统计）、撤销重做、色卡系列分组选色。
4. **文字转图纸**：输入文字/字母/数字，选字体与粗细，横排/竖排，自动生成。
5. **描摹模式**：上传参考图半透明垫底，逐格描点（手作还原玩法）。

**制作辅助（图纸生成后）**

* 按色聚焦模式：高亮当前色号、逐色标记完成、自动切换下一色，匹配玩家"按颜色批量铺豆"的真实工作流。
* 底板布局：按 2.6mm / 5mm 常见实体底板规格计算所需板数，图纸标接板缝线，图案居中提示。
* 孤豆检测：标记四周无相邻豆的孤立豆（制作时易脱落、易漏拼），提示用户加锚或修改。
* 用量估算：按色号统计颗数 + 按每包豆数估算采购包数；导出 CSV / Excel 材料清单。
* 色差提示：生成时明示"屏幕色仅近似实物色，大批量采购前请以实物色卡核对"。
* 图纸导出选项：色号模式 / symbol 符号模式（小格子用符号+图例）、网格线密度、坐标轴、300 DPI 打印友好 PNG、远期 PDF 分块打印。
3. **文字转图纸**：输入文字/字母/数字，选字体与粗细，自动生成。
4. **描摹模式**：上传参考图半透明垫底，逐格描点（手作还原玩法）。

### 3.3 我的（Tab 3）

* 我的作品：进行中 / 已完成 / 收藏的模板，支持进度打卡（按 10x10 分块勾选）。
* 我的豆库：登记已持有色号与数量（可按 MARD 收纳盒布局登记位置）；生成图纸时自动标记"已有/缺料"，生成缺料清单（可复制文本），进阶可显示"豆子在你收纳盒的第几格"。
* 导出历史：图纸 PNG / PDF（PDF 远期）。
* 设置：默认色卡、默认尺寸、清除缓存。

### 3.4 内容与引导

* 新手教程：拼豆是什么、工具清单、熨烫技巧（图文 + 视频），运营后台可维护。
  * 教程内容直接采用深度调研结论：三种熔法（部分熔/全平融/背熔）选择、胶带法步骤与防爆孔、熨斗温度与画圈手法、失败案例图解、裱框与展示。
* 色卡百科：全部色号色卡对照浏览 + 搜索（色号查颜色 / 颜色查色号）。

## 四、Web 管理后台规划

### 4.1 模块

1. **登录与权限**：管理员账号，角色分超管 / 运营 / 审核。
2. **色卡管理**：品牌、色号、色名、HEX、排序维护；小程序端接口动态下发；支持 Excel 批量导入。
3. **模板管理**：上传模板（网格数据 JSON + 预览图 + 分类标签 + 来源标记）、编辑、上下架、排序、推荐位配置。
4. **投稿审核**：审核队列，预览大图 + 数据校验，通过 / 驳回（附理由），先审后发。
5. **用户管理**：用户列表、搜索、封禁/解封、用户作品管理（违规下架）。
6. **内容管理**：教程文章、公告、Banner、分类标签字典维护。
7. **数据看板**：DAU、图纸生成量、模板热度榜、投稿量/审核通过率、留存概览。

### 4.2 技术选型建议

* 前端：Vue 3 + Vite + Element Plus（与小程序同为 Vue 技术栈，团队认知成本低）。
* 部署：云服务器 / 容器平台均可，注意 HTTPS 与微信 request 合法域名配置。

## 五、技术架构建议

### 5.1 总体

```
微信小程序（Taro 4 + Vue 3 + Pinia + TS）
        |
微信云开发（推荐 M1-M2）           自建后端（M3+ 可选演进）
  云函数（API）                    Node.js (NestJS) + MySQL
  云数据库（文档型）                + Redis（热模板缓存）
  云存储（图片/OSS）                + OSS（图片）
        |                                  |
        +--------- Web 管理后台（Vue 3 + Element Plus）---------+
```

**云开发 vs 自建**：

* 云开发：免运维、免备案、免域名白名单，云函数 + 云数据库 + 云存储开箱即用，适合快速上线验证；缺点是迁移锁定与复杂查询弱。
* 自建：完全可控、便于后续多端（H5/App）与电商扩展；代价是服务器、备案、运维。
* 建议：**M1/M2 用微信云开发快速上线**，数据模型按可迁移设计（JSON 文档结构），M4 若商业化验证成功再评估迁移自建。

### 5.2 核心算法（图片转图纸）

完整管线（吸收 Zippland、perler-beads-ai、Pindou、豆格工坊、Jett-Wu 五个项目的已验证实践）：

1. AI 预处理（可选，差异化）：照片先转干净的像素风插画再量化，规避照片渐变带来的杂色灾难。
2. 裁剪与重采样：按目标网格划分单元，**面积采样取主导色（众数）而非均值**，避免色块边界出现灰色毛边（行业公认的初代痛点）。
3. 双模式策略：Photo 模式保留过渡（配可选抖动），Illustration 模式保护边缘与色块纯净。
4. 减色：Median Cut 或 K-means，K = 用户选的颜色数。
5. 色卡映射：在感知色彩空间中找最近色，首选 OKLab 或 CIEDE2000（色卡数据库带 LAB 值），RGB 欧氏距离仅作兜底。
6. BFS 杂色合并：相似色连通区域统一为区域众数色号，可调阈值。
7. 背景移除：定义背景色号列表，从边界洪水填充标记"外部"，统计与导出均忽略。
8. 颜色排除与重映射：用户排除某色号后，在剩余可用色中找最近似色重映射。
9. 后处理校验：孤豆检测（四周无相邻豆）、信息容量提示（如 16x16 只有 256 格，小于一格的细节明确提示无法还原，不静默声称完美）。
10. 输出：网格颜色索引矩阵（压缩存储）+ 按色号用量统计 + 按包数估算 + 高清图纸 PNG（色号模式 / symbol 符号模式）。

性能要点：大图转换放 Web Worker（小程序端可用分帧渲染或 Worker），结果可取消、可复现（同参数同结果），建立测试图集（人像/风景/动漫/线稿）做回归调参。

### 5.4 内容安全与合规（微信审核硬门槛）

1. UGC 必须接微信内容安全接口：图片 `imgSecCheck` / 异步 `mediaCheckAsync`，文本 `msgSecCheck`。
2. 投稿先审后发：机器审 + 人工审双保险。
3. 举报通道 + 违规下架流程。
4. 版权：官方模板用原创/无版权素材；用户投稿协议要求原创授权；提供侵权投诉入口。
5. 隐私：相册/头像等权限用途说明，隐私协议接入微信隐私弹窗。
6. **开源许可红线**（深度调研关键结论）：
   * Zippland/perler-beads（933 星）为 **AGPL-3.0**：严禁复制其代码用于闭源商业产品；算法思想（主导色、BFS 合并、洪水填充）不受版权保护，须完全自研实现。
   * liangdabiao/perler-beads-ai（当前小程序母项目）、豆格工坊、Pindou 社区版为 **Apache-2.0**：允许商业复用，但须保留版权与许可声明、修改说明。
   * beadcolors 色卡数据库为开源数据，引用时保留来源记录（contributor/provenance）。
7. **商标合规**：MARD、Artkal、Hama、Perler 是第三方商标，产品内不得暗示官方合作或背书；色卡数据页应标注"仅为色彩对照参考，与品牌无隶属关系"。

## 六、商业化思路（打开思路）

1. **免费 + 激励视频广告**：高清无水印导出、批量转换解锁看广告，最轻的变现起点。
2. **会员订阅**：高级滤镜/人像模式、批量生成、PDF 导出、专属会员模板、更大云空间。
3. **缺料清单 -> 电商闭环**（远期）：图纸生成色号清单后，展示"一键配齐材料包"，自营发货或带货分销（拼豆品牌合作）。
4. **品牌合作**：与 MARD 等国产拼豆品牌联名官方色卡、定制模板，导流线下。
5. **社区活动**：每周主题挑战赛（节日热点），带动留存与 UGC。

**暂不建议**：初期不做付费模板抽成等重运营模式，先把工具口碑和模板量做起来。

## 九、关键风险

1. **微信审核**：UGC 小程序类目资质（社交/社区类可能要求个人主体不可用，需企业主体）、内容安全接口接入完整性是最大门槛。
2. **图片存储成本**：模板预览图与图纸图走云存储，需压缩 + CDN + 生命周期策略。
3. **算法效果**：色卡映射准确度决定口碑，需要建立测试图集持续调参（人像/风景/动漫分别调优）。
4. **版权风险**：动漫角色模板天然高风险，投稿协议 + 审核标准 + 投诉通道三件套必须齐。
5. **开源许可风险**：必须区分借鉴与抄袭的边界。Zippland 系（AGPL-3.0）代码一行都不能进闭源商业仓库；可安全继承的是 Apache-2.0 项目（perler-beads-ai、豆格工坊、Pindou 社区版）的代码与算法实践，以及 beadcolors 的开放色卡数据，均需保留许可与来源声明。算法层建议完全自研实现，仅参考公开的算法思路。
